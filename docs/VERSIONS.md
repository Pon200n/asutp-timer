# Рабочие версии ASUTP Timer — куда откатываться

Таблица сборок, проверенных на устройстве. **Основной идентификатор — короткий
sha коммита**: по нему в любой момент собирается тот же APK.

## Нумерация версий

**Номер версии = порядковый номер коммита в истории репозитория** (`git
rev-list --count HEAD`). Он известен ДО коммита — поэтому пишется в его
заголовок («#63 …») и всегда совпадает с номером в приложении и в релизе.

| где | что |
|---|---|
| Заголовок коммита в GitHub | `#63 Секция 03: …` |
| Приложение (карточка «07 // Настройки») | `сборка #63 · <sha> · версия 1.0.63 · собрано …` |
| Releases | релиз назван **«Build Android APK #63»** |
| Система (Настройки → Приложения) | `версия 1.0.63` |

Номер прогона CI (в Actions) — отдельная метрика: он считает все запуски,
включая перезапуски вручную, и с номером версии не совпадает. Ориентироваться
надо на **номер версии** — он есть в заголовке коммита, в приложении и в
релизе.

## Как проверить, что стоит на телефоне

```bash
adb shell "sha256sum \$(pm path com.asutp.timer | sed 's/package://' | tr -d '\r')"
```

Сравните с колонкой «sha256 APK». Номер сборки и версия видны прямо
в приложении — карточка «07 // Настройки приложения», верхняя строка:
`сборка #51 · aa1102e · версия 1.0.51 · собрано 23.11 11:50`.

До сборки #50 в манифесте стояло `versionName "1.0"` для всех сборок — тогда
идентификатором был только sha.

## Как откатиться

1. **Пересобрать нужный коммит в CI:** Actions → «Build Android APK» →
   Run workflow → указать ревизию (ветку/тег/коммит) → дождаться сборки.
   APK появится в релизе `latest` (файл заменяется свежим).
   Либо локально:
   ```bash
   git checkout <sha>
   npm install && node tools/sync-vendor.js && npx cap sync android
   cd android && ./gradlew assembleDebug
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```
2. **Ставится поверх** (`install -r`): подпись постоянная, поэтому
   разрешения и настройки сохраняются, снос приложения не нужен.
3. **Сверить результат** по sha256 (см. выше) — с таблицей.

## Откат прямо с телефона

Эталонный APK **1.0.66** лежит в памяти телефона:

```
/sdcard/Download/ASUTP_STABLE/asutp-timer-1.0.66.apk
sha256 5f9989743c730a484b45dc205f81f00d93d8f43eefa7312cbb63f9130ceecc58
```

Это точная копия установленной сборки (вытянута с телефона, не пересобрана).
Откат: Файлы → Загрузки → ASUTP_STABLE → этот APK → установить. Потребуется
разрешение «Установка из неизвестных источников» для приложения «Файлы» — один раз.

Запасной путь: в релизе после изменения публикации будут лежать копии сборок с
номерами (`asutp-timer-build-<N>.apk`) — страница релиза открывается в браузере
телефона, оттуда скачивается нужная версия.


## Отличия рабочих версий (что важно знать при откате)

| | #66 — **стабильная** (на телефоне) | #70 — текущая в репозитории |
|---|---|---|
| Логика тревог (`alerts.js`, `shift.js`, `state.js`, `AsutpAlarmReceiver`) | — | **не менялась** ✓ |
| Нативный плагин | без `getBuildInfo` | + метод `getBuildInfo` (только чтение) ✓ |
| Интерфейс | без карточек блоков в расписании | + карточки блоков в разделе 05 ✓ |
| Манифест | `versionName "1.0.66"`, `versionCode 66` | `versionName "1.0.70"`, `versionCode 70` |

То есть **#70 функционально совпадает со стабильной #66** — разница только в
оформлении расписания. Откатываться не нужно; если понадобится именно
бинарник #66 — он уже лежит на телефоне (см. «Откат прямо с телефона»).

⚠ **Не проверено на устройстве:** сборки после #66 (то есть #70) — в бою не
работали. Стабильной считается #66, пока новая не пройдёт боевую проверку.
