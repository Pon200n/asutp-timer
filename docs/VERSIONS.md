# Рабочие версии ASUTP Timer — куда откатываться

Таблица сборок, проверенных на устройстве. **Основной идентификатор — короткий
sha коммита**: по нему в любой момент собирается тот же APK.

## Как проверить, что стоит на телефоне

```bash
adb shell "sha256sum \$(pm path com.asutp.timer | sed 's/package://' | tr -d '\r')"
```

Сравните с колонкой «sha256 APK». Номер сборки и версия видны прямо
в приложении — карточка «07 // Настройки приложения», верхняя строка:
`сборка #51 · aa1102e · версия 1.0.51 · собрано 23.11 11:50`.

До сборки #50 в манифесте стояло `versionName "1.0"` для всех сборок — тогда
идентификатором был только sha.

## Как откатиться

1. **Пересобрать нужный коммит в CI:** Actions → «Build Android APK» →
   Run workflow → указать ревизию (ветку/тег/коммит) → дождаться сборки.
   APK появится в релизе `latest` (файл заменяется свежим).
   Либо локально:
   ```bash
   git checkout <sha>
   npm install && node tools/sync-vendor.js && npx cap sync android
   cd android && ./gradlew assembleDebug
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```
2. **Ставится поверх** (`install -r`): подпись постоянная
   (`keystore/debug.p12`), поэтому разрешения и настройки сохраняются,
   снос приложения не нужен.
3. **Сверить результат** по sha256 (см. выше) — с таблицей.

## Отличия рабочих версий (что важно знать при откате)

| | #46 (боевая) | #51 (текущая) |
|---|---|---|
| Логика тревог (`alerts.js`, `shift.js`, `state.js`, `AsutpAlarmReceiver`) | — | **не менялась** (diff пустой) |
| Нативный плагин | без `getBuildInfo` | + метод `getBuildInfo` (только чтение) |
| Интерфейс | без строки версии | + строка версии в настройках |
| Манифест | `versionName "1.0"`, `versionCode 1` | `versionName "1.0.51"`, `versionCode 51` |

То есть **#51 функционально совпадает с боевой #46** — разница только в строке
с номером сборки. Откатываться не нужно; если понадобится именно бинарник
#46 — соберите коммит `4ea07eb`.
